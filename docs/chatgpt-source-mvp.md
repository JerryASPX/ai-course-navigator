# AI 職涯與課程導航 MVP 開發文件

> 專案名稱：AI 職涯與課程導航
> 服務對象：想上 AI 課程的客戶、恆逸教育訓練中心非技術型業務
> 第一版範圍：AI 課程導覽、問卷分流、課程推薦、學習路線、流程圖、客戶提問、名單收集
> 目前階段：先完成可操作 MVP，不做完整官網串接與正式部署

## 1. 背景與問題

恆逸官網 AI 課程涵蓋職場應用、AI 自動化、AI 協作開發、生成式 AI 應用開發、資料科學與機器學習、企業 AI 導入與雲端等不同方向。一般客戶不知道自己適合哪一類課程，非技術型業務也不容易詳細解釋 Python、LLM、RAG、AI Agent、機器學習等技術差異。

本工具透過白話問卷協助客戶找到學習起點，並讓業務可以使用同一份結果向客戶說明。

## 2. 產品目標

1. 讓客戶回答 8～10 題後，了解自己適合的 AI 學習方向。
2. 推薦 1 門首選課程與最多 2 門備選課程。
3. 產生個人化課程學習路線。
4. 產生一張可下載的學習路線流程圖圖片。
5. 提供「其他建議」與「不建議直接上的課程」說明。
6. 提供以課程資料為依據的客戶提問功能。
7. 收集客戶問卷資料、聯絡資料與提問內容，供業務追蹤。
8. 支援每週更新 AI 課程資料；新增課程先進入待確認狀態，不能直接公開推薦。

## 3. 非目標

第一版不包含：

- 正式登入、權限管理與 CRM 整合
- 直接修改 uuu.com.tw 官網資料
- 自動報名或付款
- 以大型語言模型自由決定推薦結果
- 正式心理測驗或能力認證
- 納入非 AI 課程
- 自動寄送行銷信
- 以 AI 圖像模型產生流程圖

流程圖必須由結構化資料產生 SVG／PNG，確保中文、課程名稱與連結正確。

## 4. 六大 AI 學習方向

### AI-01 職場 AI 應用與生產力

適合行銷、業務、行政、人資、PM、一般職場人員與不想寫程式的主管。

標籤：ChatGPT、Gemini、NotebookLM、AI 簡報、AI 文件、AI 影像、AI 影片、提示設計、商務應用。

### AI-02 AI 自動化與工作流程

適合想自動化重複工作、串接表單／Email／LINE／CRM、建立 AI Workflow 的人員，不限技術背景。

標籤：n8n、Dify、AI Workflow、AI Agent、RAG、MCP、API 串接、RPA、流程自動化。

### AI-03 AI 協作程式開發

適合軟體工程師、網頁開發者、IT 人員、想轉職程式開發且已有程式基礎的人員。

標籤：GitHub Copilot、Claude Code、Codex、AI Pair Programming、Python、全端開發、測試、除錯、GitHub。

### AI-04 生成式 AI 應用開發

適合想把 AI 放進網站／App、使用 API、建立聊天機器人、RAG 或 AI Agent 的人員。

標籤：Python、OpenAI API、Gemini API、LLM、RAG、LangChain、向量資料庫、AI Agent、API 開發。

### AI-05 資料科學、機器學習與深度學習

適合資料分析師、資料工程師、資料科學家、ML Engineer 與想研究模型的人員。

標籤：Python、NumPy、Pandas、Scikit-Learn、機器學習、深度學習、TensorFlow、Keras、OpenCV、NLP、模型訓練。

### AI-06 企業 AI 導入、治理與雲端

適合企業主管、IT 主管、數位轉型負責人、PM、企業架構師與 AI 導入專案負責人。

標籤：AI Strategy、AI Governance、AI Roadmap、ROI、企業轉型、AI 專案管理、AWS AI、Azure AI、Google Cloud AI、MLOps、資安與法遵。

## 5. MVP 課程資料

請建立一份本地 JSON 課程資料，先放入下列代表性課程。每門課程必須包含：

- course_id
- code
- name
- primary_category
- tags
- level：入門／基礎／中階／進階
- target_roles
- plain_description
- sales_description
- prerequisites
- needs_programming：否／少量／是
- needs_python：否／建議／是
- needs_ml_basics：否／建議／是
- hours
- price
- course_url
- schedule_url（可為空）
- status：active／inactive／pending_review
- recommended_before：課程 ID 陣列
- recommended_after：課程 ID 陣列
- faq：問題與答案陣列

初始課程至少包括：

1. AI 工作坊：組建與指揮整合 AI 工具成為你的工作團隊
2. Google 生成式 AI－Gemini 全攻略
3. PowerPoint 簡報設計與整合 AI 生成
4. 零程式碼 AI Agent 開發實戰－使用 Dify／n8n
5. 生成式 AI 實戰演練使用 Python 語言
6. 使用 AWS 開發生成式 AI 應用程式
7. 使用 Google Cloud 開發大語言模型（LLM）應用程式
8. Anthropic Claude Code AI 協作程式開發課程
9. 使用 GitHub Copilot 提高 Coding 生產力
10. Python 機器學習－使用 Scikit-Learn
11. Python 與機器學習深度學習－使用 Keras 與 TensorFlow
12. Python 中文自然語言 NLP 深度學習與大型語言 LLM 專家課程
13. 推動組織中的 AI 轉型
14. Generative AI Essentials on AWS

課程 URL 必須回到 uuu.com.tw 對應的課程介紹頁；不可使用假的 `/course/1` 連結。若某課程無法確認 URL，該課程標記 pending_review，不可作為推薦結果。

## 7. 分流規則

不使用分數。使用優先順序與條件判斷：

1. Q1 的明確目標優先決定主要學習方向。
2. 若 Q1 是轉職或不確定，使用 Q2、Q4、Q5、Q6、Q8 共同判斷。
3. 沒有程式經驗者，不直接推薦需要 Python 的 AI-04 或 AI-05 課程；應先推薦 AI-01、AI-02 或 Python 入門路線。
4. 有 Python／開發經驗且目標為網站、App、API、聊天機器人，推薦 AI-04。
5. 有程式經驗且目標為提升開發效率，推薦 AI-03。
6. 有 Python 且目標為模型訓練、資料分析、演算法，推薦 AI-05。
7. 主管、PM、企業導入需求優先考慮 AI-06；若同時有明確技術開發目標，再附加 AI-03 或 AI-04。
8. 不確定時，推薦「AI 探索／職場應用」起點，並提供免費講座與業務諮詢，不要推薦高階課程。
9. 推薦課程必須符合先備條件，且 `status=active`、`course_url` 有效。
10. 若沒有完全符合的課程，顯示「建議洽業務確認」，不可硬湊推薦。

## 8. 結果頁內容

結果頁必須包含：

1. 你的 AI 學習方向
2. 為什麼推薦這個方向
3. 你的目前程度與可能能力缺口
4. 首選課程
5. 最多兩門備選課程
6. 每門課程的「查看官網課程介紹」連結
7. 若有資料，提供「查看開課時間」連結
8. 若無公開班次，顯示「目前尚未查到公開班次，請洽業務」
9. 個人化課程學習路線
10. 學習路線流程圖
11. 不建議直接上的課程與原因
12. 其他建議
13. 客戶提問區
14. 預約業務／留下問題 CTA

## 9. 流程圖規格

由學習路線 JSON 自動產生 SVG，並提供下載 PNG 或 SVG。

節點至少包含：

- 目前程度
- 前置能力
- 首選課程
- 後續課程
- 進階方向

視覺建議：

- 深藍底
- 青色主路線
- 金色標示首選課程
- 灰色標示未來進階課程
- 紅色標示先備能力不足或注意事項
- 中文文字必須直接來自資料，不得由圖像模型重新生成

## 10. 客戶提問功能

第一版可以先使用本地 FAQ／課程資料回答，不必先接外部 LLM API。介面需支援：

- 快速問題按鈕
- 自由輸入問題
- 顯示相關課程連結
- 顯示回答依據的課程
- 「請業務協助」按鈕
- 問題保存到該次客戶紀錄

預設快速問題：

- 沒有 Python 可以上嗎？
- AI Agent 和 ChatGPT 有什麼不同？
- 我是行銷人員，需要學 Python 嗎？
- 想做企業內部問答機器人，應該學哪門課？
- 這門課和 n8n 課程有什麼不同？
- 我應該先學機器學習還是生成式 AI？

若問題涉及以下內容，必須轉人工，不可猜測：

- 最新優惠
- 確切開課與候補
- 退費規則
- 補助資格
- 客製化包班
- 講師安排
- 個別付款或行政問題

## 11. 客戶資料收集

問卷完成後收集：

### 必填

- 姓名
- Email 或手機至少一項
- 身分類型
- 希望聯絡方式

### 選填

- 公司名稱
- 職稱
- 希望上課地點
- 預計上課時間
- 是否有企業包班需求
- 想詢問的問題

需要區分：

- 同意查看推薦結果
- 同意接受課程資訊
- 同意業務聯絡

不得把行銷同意默認為必勾。

## 12. 業務模式

MVP 至少提供一個「業務解說版」切換，內容包括：

- 客戶類型
- 推薦主方向
- 推薦原因
- 目前程度
- 先備能力警示
- 首選與備選課程
- 建議業務話術
- 複製課程介紹連結
- 複製結果頁連結
- 客戶提問紀錄

## 13. 每週課程更新設計

先建立本地同步介面與狀態，不必在 MVP 直接實作正式爬蟲，但資料模型必須支援：

- `last_synced_at`
- `last_verified_at`
- `source_url`
- `status`
- `pending_review_reason`
- `replacement_course_id`

每週更新流程：

1. 讀取官網 AI 課程清單。
2. 比對課程代碼、名稱與 URL。
3. 標記新增、修改、下架課程。
4. 新課程建立為 `pending_review`。
5. 課程內容異動時重新檢查分類與先備條件。
6. 課程頁失效時停止推薦，但保留歷史紀錄。
7. 人工確認後才轉為 `active`。

## 14. 建議 MVP 技術要求

若專案尚無既有技術限制，使用簡單、可本機執行的方案：

- 前端：React + Vite 或既有專案適合的前端框架
- 樣式：現代響應式 CSS
- 資料：本地 JSON，避免第一版依賴資料庫
- 流程圖：純 SVG 產生器
- 匯出：瀏覽器可下載 SVG；PNG 可使用 canvas 或 SVG 轉換
- 問卷：前端狀態管理即可
- 儲存：MVP 可先使用 localStorage，並保留未來 API 介面
- 測試：至少涵蓋分流規則、課程 URL、先備條件與流程圖資料

## 15. 驗收標準

### 問卷

- 可以完成完整 10 題流程。
- 具備條件分流，不使用分數。
- 每個選項都有清楚中文說明。
- 有「不確定」選項。
- 未填必要答案時有提示。

### 課程推薦

- 至少能產生六大方向之一。
- 首選課程最多一門，備選課程最多兩門。
- 不推薦不符合先備條件的高階課程。
- 每個推薦課程都有正確官網介紹連結。
- 無有效課程時顯示洽詢業務，不產生假推薦。

### 學習路線與圖片

- 每個結果都有學習路線。
- 流程圖節點與文字來自課程資料。
- SVG 可下載。
- 流程圖中文字不被截斷。
- 首選課程能在圖中明顯辨識。

### 客戶資料

- 問卷結果與客戶資料可以一起保存。
- 可以記錄客戶提問。
- 行銷同意與業務聯絡同意分開。
- 業務可以查看白話推薦原因與課程 URL。

### 更新狀態

- 新增課程可標記為待確認。
- 下架課程不再被推薦。
- 課程介紹連結失效時有錯誤狀態。

## 16. Codex 執行要求

1. 先檢查專案現況，再決定實作方式。
2. 優先完成可操作 MVP，不要只做靜態畫面。
3. 若課程資料與官網內容無法確認，標記待確認，不要捏造。
4. 不要新增需要 API key 的服務。
5. 使用繁體中文與台灣用語。
6. 課程推薦核心使用明確規則，AI 問答先使用本地資料與 FAQ。
7. 完成後執行測試與本機啟動驗證。
8. 回報實際修改的檔案、啟動指令、測試結果與尚未完成項目。
9. 不要自行提交到 GitHub 或部署外部服務。
10. 不要修改其他專案。
